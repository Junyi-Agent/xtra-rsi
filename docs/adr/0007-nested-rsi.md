# 0007 嵌套 RSI：每个节点自己决定要不要给某个阶段开 sub-RSI

状态：采纳（2026-11-21 用户授权先实现第 1 步，之后再审阅决策）

## 背景

0.2 的 loop 只改进任务（例如 fraud 模型）；各阶段的规则（AGENTS.md、scripts、data）只由人改。要让「怎么观察、怎么推理、怎么决策」本身也被自动改进，阶段本身需要成为被改进的对象，即每个阶段可以有自己的 RSI（sub-RSI），sub-RSI 的阶段又可以再有自己的 sub-RSI。

嵌套几层事先不知道，也不应写死：由每一层根据证据和预算自己决定。

## 决策

### 节点：每一层都是同一种 RSI

一个 RSI 节点 = 目标 + 指标 + 预算 + 五个阶段。

- 根节点的目标是任务本身（由下游项目配置）；其他节点的目标是父节点某个阶段的目录（`AGENTS.local.md`、`scripts/`、`data/`）。
- 所有节点用同一套基础层五阶段规则，不为每一层另写 AGENTS.md。节点的差异只在约定（见下）里。
- 深度没有上限常量。

### 局部视野

每个节点只读三样东西：

| 读 | 不读 |
|---|---|
| 父节点给它的**约定**：目标、指标、限制、预算、截止时间 | 祖父及以上节点、整棵树的结构和深度 |
| 自己的五个阶段，以及其中哪些阶段开了 sub-RSI | 子节点内部的运行过程和更深的节点 |
| 子节点交上来的**摘要**：提出的改动、证据、花费、状态 | |

- 往下传：约定。往上交：改动 + 证据。父节点用**自己的**评估决定是否接受。
- 子节点不能直接改父节点的任何文件；它的产出是一个「对目标目录的改动提案」，由父节点的 action 阶段应用。

### 开 sub-RSI 是 decision 阶段的一个选项

- 和「改特征」「调参数」并列，decision 可以选择「为阶段 X 开 sub-RSI」，reasoning 要给出证据：失败集中在阶段 X（例如回放显示多数被回滚的改动源于 observe 漏掉的信息）、阶段 X 已有足够的回放数据、预算足够。
- **开 sub-RSI 必须经人确认。** 申请进入 `pending_approval`，由人运行 `rsi approve <node>` / `rsi reject <node>`；未确认前不运行、不花预算。这一条在嵌套机制被验证（本 ADR 改为「已验证」）后再讨论是否放宽。
- 子节点连续 K 轮没有被父节点接受的改动时撤销（`retired`），父节点在 feedback 的 `lessons` 里记下「为 X 开 sub-RSI 无效」及原因。

### 预算按金额

- 预算单位是金额（美元）。花费由 token 用量按模型单价换算：框架提供单价表，下游可覆盖。
- 每次 LLM 调用都记账到发起它的节点；节点花费超过预算时停止并上报父节点。
- 开 sub-RSI 时从自己的剩余预算里**划出**一部分给子节点（预算只分不增）。子节点未用完的预算在撤销或结束时退回父节点。

### 为什么会停下来

不靠层数上限，靠三个越往下越难满足的条件：

1. **预算只分不增**：每层可用的钱单调减少，到一定深度不足以再开。
2. **回放数据变少**：子节点评估用的数据来自父节点的运行记录，越深越少；数据不足时 reasoning 不应申请开 sub-RSI。
3. **必须有收益**：没有被接受的改动就被撤销。

另外每次开 sub-RSI 都要人确认，在验证阶段也是兜底。

### 子节点怎么评估：回放

完整 ablation 要把父 loop 跑两遍，不能作为子节点每一轮的评估。子节点用**回放**：

- 父节点 `runs/` 里记录了目标阶段每一轮的输入（upstream）、输出，以及这一轮最终是否被保留（feedback 的 `verdict`）。
- 子节点改完目标阶段后，用历史输入重跑该阶段，用回放评分函数比较新旧输出。评分函数由下游按业务提供（例如「reasoning 的假设是否命中最终被 keep 的改动」），框架提供回放的执行和记录。
- 回放数据按产生它的 harness 版本（commit）标记；目标阶段的上游被改过之后，旧数据标记为过期，不再用于评估。

完整 ablation 只在父节点接受子节点改动前跑一次，作为把关。

### 防止优化方向跑偏

层越深，指标离真正目标越远（「指标的指标」）。

- **逐层把关**：子节点的改动必须通过父节点的评估才被应用；父节点的改动（包括应用了子节点提案后的阶段）又要通过祖父节点的评估。改进只能一层层往上传。
- **根节点定期回归**：根节点每 M 轮重跑自己的阶段 ablation 和任务指标，不需要知道下面的树。变差时回滚最近接受的改动。
- **不能改评估**：任何节点都不能修改父节点交给它的指标、评估脚本、回放数据，也不能改自己的 `evals/`。由脚本强制（扩展 `git_guard.py` 或在应用提案前检查改动路径），不只写在文档里。
- **一次只接受一个子节点的改动**：多个子节点同时提案时，父节点逐个应用和评估，保证指标变化能归因。

### 文件布局

用扁平的节点表，不按树形嵌套目录：

```
rsi/nodes/<id>/node.yaml      # parent、target、metric、budget、spent、status、created_by
rsi/nodes/<id>/contract.yaml  # 父节点给的约定（只读）
rsi/nodes/<id>/summary.yaml   # 交给父节点的摘要
rsi/nodes/<id>/runs/          # 本节点的运行记录
```

`status` 取值：`pending_approval`、`running`、`proposed`、`rejected`（人拒绝了申请）、`retired`、`done`。节点只按上面「局部视野」读文件，由框架提供的读写接口保证。

### 框架与下游的分工

| xtra-rsi | 下游（例如 fraud-rsi） |
|---|---|
| 节点表、约定、摘要的格式和读写 | 根节点配置：目标、指标、总预算 |
| decision 的「开 sub-RSI」选项和审批命令 | 各阶段 `AGENTS.local.md` 的业务规则 |
| 预算记账、单价表、预算划分和退回 | 回放评分函数 |
| 回放执行、数据版本标记 | 业务数据、训练和评估脚本 |
| 撤销规则、根节点定期回归、不能改评估的强制检查 | |

### 实现顺序

1. 节点表、约定、摘要、预算记账、审批命令。只开到第一层，但数据结构和接口不假设深度。
2. 在 fraud-rsi 接入，产生真实运行记录，验证回放评估和「要不要开 sub-RSI」的判断。
3. 根据 fraud-rsi 的结果修改，再放开更深的嵌套。

## 后果

- LLM 调用随嵌套深度成倍增加；预算记账成为必需功能，不再是可选项。
- 回放评估依赖下游写评分函数，框架无法独立判断阶段输出的好坏。
- 人工审批会让 loop 停下等人；长时间运行的项目需要通知机制（未在本 ADR 范围内）。
- 公开接口新增：节点表格式、约定和摘要格式、`rsi approve` / `rsi reject` 等命令，变更按 AGENTS.md 的公开接口规则处理。

## 待定

- 撤销阈值 K、根节点回归间隔 M 的默认值。
- 单价表的来源和更新方式。
- 预算划分比例由父节点的 decision 决定，还是框架给默认比例。

## 实现记录（第 1 步）

- `xtra_rsi.nodes`：节点表、约定、摘要、花费流水；`NodeView` 只暴露自己、约定和子节点摘要。批准时从父节点剩余预算划出（`allocated_usd`），结束时花费并入父节点 `spent_usd`、余额退回；有未结束的子节点时不能结束父节点。批准时用 `rsi sync` 生成子节点自己的 harness，子节点因此也能再申请子节点（代码里没有深度假设）。
- `xtra_rsi.node_loop.run_node`：通过 `run_loop` 新增的 `on_output` 钩子实现。阶段输出的 `_usage` 记账后删除；decision 的 `spawn_request` 生成待确认子节点，结果（或错误原因）写入 `spawn_request_result`，不中断 loop；feedback 输出注入最新的 `_node` 视野。超支时先记账再停止（`StopLoop`），无法换算金额时也停止。
- `xtra_rsi.pricing`：默认单价表只收录官方公布的价格（2026-11），未公布的缓存价格留空；用量里出现没有单价的 token 时报错而不是猜。
- `rsi approve` / `rsi reject` 由 `git_guard.py` 拒绝 agent 通过 Bash 运行；人用 `!` 在会话里运行或在自己的终端运行。

尚未做到：

- 人工审批只拦住了命令行；agent 仍可以用文件编辑工具直接改 `node.yaml`。需要再加一层保护（例如 PreToolUse 拦截对 `rsi/nodes/**/node.yaml` 的写入）。
- 「不能改评估」的强制检查、回放评估、提案的应用与把关、根节点定期回归、自动撤销，属于第 2、3 步。
- 节点表只支持单进程写入。
